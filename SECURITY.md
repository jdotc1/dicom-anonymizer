# Security and sensitive-data reporting

The project's security contact is GitHub private vulnerability reporting. In the public repository, open the Security tab, choose Advisories, then select Report a vulnerability. Reports go privately to repository administrators/security managers; do not file security-sensitive details as a public issue.

The reporting channel is GitHub’s private vulnerability reporting for this repository. If the button is unavailable, ask for it to be restored without including exploit details, patient data or sensitive samples. No dedicated security email address is claimed.

Use entirely synthetic reproductions. Never attach patient datasets, identifiers, original clinical filenames, credentials, or unredacted logs to reports, issues, pull requests or discussions, including private reports. Describe a suspected disclosure using fabricated values and the affected attribute names or code paths.

For an ordinary bug, provide the app/policy version, operating-system version, expected behavior and a synthetic reproduction. Maintainers should monitor GitHub Security alerts and their private-report notifications; no response-time guarantee or supported binary maintenance period has been announced.

The current release is a source preview with runtime acceptance pending. The tool retains pseudonyms, pixels and selected descriptors; a successful metadata audit is not proof that all identifiable content has been removed.
