# Security and sensitive-data reporting

Do not attach patient datasets, patient identifiers, original filenames, credentials, or unredacted logs to public issues, pull requests or discussions. Use an entirely synthetic reproduction.

For an ordinary bug, provide the app/policy version, operating-system version and a synthetic example. For a vulnerability or possible sensitive-data disclosure, use GitHub's private vulnerability reporting when enabled by the project owner. Before that channel is available, do not post exploit details or sensitive samples publicly; request a private contact without including sensitive content. A dedicated public-facing security contact must be established before publication.

The current source snapshot is a review candidate. No supported binary release or security-maintenance period has been announced. The tool retains pseudonyms, pixels and selected descriptors; a successful metadata audit is not proof that all identifiable content has been removed.
