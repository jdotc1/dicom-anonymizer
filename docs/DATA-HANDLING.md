# Data handling

The input is one folder containing numeric immediate patient folders. Identifiers are at most 64 characters and are preserved exactly, including leading zeros. PatientName and PatientID are replaced recursively. Private tags, uninterpreted public UN elements, dates/times and known identifying fields are cleared or removed; retired curve groups are removed. Required type-2 fields may remain present with empty values. Internal names are generated independently of source names.

The retained contract includes SeriesDescription, ProtocolName, SequenceName, ContrastBolusAgent, SoftwareVersions, Manufacturer, image pixels, contour geometry, public quantitative measurements, ROI names and observation labels, and PatientSex/Age/Size/Weight. Removing private tags may remove vendor-specific quantitative information. Clearing dates also removes temporal information. This is not a complete IOD validator, certified confidentiality profile, visual de-identification tool or guarantee of irreversible anonymity.

Patient-specific UIDs and nested references are remapped consistently. SOP-class, transfer-syntax and explicit structural/coding identifiers are retained. File meta is rebuilt and synchronized; preambles are zeroed. A study belonging to more than one patient folder stops the batch. Shared FrameOfReferenceUID, ReferencedFrameOfReferenceUID, RelatedFrameOfReferenceUID or SourceFrameOfReferenceUID values across patient folders also stop it; repeated values within one patient remain allowed. Synchronization/equipment identifiers are outside this patient-relative spatial check. Common atlas-space workflows are not an approved exception.

MR/CT/RTSTRUCT are the supported modality labels. Symbolic links, nonregular patient-file entries, unsupported modalities, duplicate instance UIDs, invalid required UIDs, declared burned-in annotations and overlays stop the batch. Non-DICOM sidecars are excluded and counted, including recognized AppleDouble resource companions. Malformed DICOM files stop processing. The bounded pre-parser/resource envelope proposed during development is not part of this source snapshot; not every malformed-stream or resource-exhaustion case is covered.

A disk-space preflight estimates required capacity. Staged files are fully read and decoded before atomic publication, including metadata after Pixel Data. The self-audit enforces identity, date, private-tag, UN, clear/remove policy and UID invariants. Some policy lists are shared with the cleaner, so this audit is not an independent conformance oracle. Failures and handled cancellation remove staging; abrupt process death or power loss can leave hidden staging. Sources are not modified. The completed report contains pseudonyms, aggregate counts, versions and audit status, without an original identity mapping.

Review retained labels, ROI names, image text and facial anatomy before sharing. Absence of a burned-in annotation flag does not establish absence of identifying pixels. Do not upload sensitive data to the project's issue tracker.
